Found by the `oligolia-gx-tests` differential round on CRISPR (round 1). Not fixed here — this is a report, with a sealed failing test attached.

## This one is a capability gap, not wrong arithmetic

Stated plainly up front, because it separates this issue from the other six in the
round: **`CRISPRDesignRequest` has no `is_circular` field.** The router is not
ignoring information it was given — it is never given the information. Nothing in
`backend/routers/crispr.py` computes a wrong index here.

It is still the app's defect and not the caller's, because the app already knows the
molecule is circular everywhere else:

- `backend/models/sequence.py:96` — the app's own `Sequence` model carries `is_circular`.
- `backend/routers/primers.py:592` (`RestrictionRequest.is_circular`) and `:623`
  (`DigestRequest.is_circular`) — **the restriction capability already has it**, and
  honours it: `_find_sites` at `backend/routers/primers.py:570-583` does exactly the
  doubled-sequence trick this needs, and `_overhang_at`/`_cut_ends`
  (`:663-717`) keep circular coordinates modulo `n`. That is the reference
  implementation, verified by gx round 1's RE-5/RE-6 (`gx/test_restriction_circular_origin.py`).
- `gui/panels/crispr_panel.py:130` — `set_target` is handed the loaded record's
  sequence with the circularity dropped on the floor.

So designing guides against a plasmid — the single most common thing a desktop
cloning tool is pointed at — silently cannot see the junction.

## Symptom

Load pUC19 and design SpCas9 guides. The panel reports **326 candidates**. There are
**330** sites on the circle: four SpCas9 sites run through the origin and are never
searched, and the user is given no signal that a region of their molecule was
skipped.

The counts are small in absolute terms. The reason to record them is that the status
line says "N guides shown (of M candidates) for 2686 bp target"
(`gui/panels/crispr_panel.py:185`) while M was computed over a cut-open string.

## Requirement

**CR-14** (`gx/crispr/register.json`):

> Origin-spanning sites on a circular molecule. Three of the four pinned inputs are circular (pUC19 a plasmid, NC_001699.1 and AF071878.1 complete circular genomes) and the app's own sequence model carries is_circular, which the restriction capability already honours. A guide site that runs through the origin of a circular molecule is a real site; designing against a plasmid must either find those sites or the capability must be reachable with the circularity the app already knows about. Pinned: the exact candidate counts the same grammar yields on the circle versus on the cut-open linear string.

called in-process.

## Where it is

- `backend/models/crispr.py:27-36` — `CRISPRDesignRequest`: `target_sequence`,
  `cas_type`, `guide_length`, `max_guides`, `check_off_targets`,
  `reference_sequences`, `max_mismatches`. **No `is_circular`.**
- `backend/routers/crispr.py:76-98` — the target is normalised, validated and
  length-checked as a flat string.
- `backend/routers/crispr.py:108`, `:123` (Cas9 ± strand), `:143`, `:157` (Cas12a ±
  strand), `:176` (Cas13) — every scan walks the linear string, so no window can
  straddle index 0.
- `gui/panels/crispr_panel.py:130` — `set_target(seq)` receives only the sequence
  text; the record's `is_circular` never reaches the request.

## The fix already exists in this repo

`backend/routers/primers.py:570-583`:

```python
def _find_sites(template: str, recog: str, is_circular: bool) -> list[int]:
    ...
    if is_circular and k > 1 and n >= k:
        ...
```

Same doubled-sequence trick, same de-duplication problem already solved. What this
needs is: `is_circular: bool = False` on `CRISPRDesignRequest`, the scan run over
`target + target[:L + pam_len - 1]` when set, positions reported modulo `len(target)`,
each site counted once — and the GUI passing the loaded record's circularity through
`set_target`.

Off-target scanning (`backend/crispr_offtarget.py:71-99`) would want the same
treatment for consistency, since it scans `[target, *reference_sequences]` with the
same linear window logic. Not covered by CR-14 and not asserted by the sealed tests.
