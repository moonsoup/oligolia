## Requirement

**OR-11** — *Layout characters do not move the ORF coordinates. NG_007400.1's bases wrapped at 60 columns with CRLF line endings denote the same 24,544-base molecule: `sequence_length` must be 24544 and the reported ORF set must be identical to the unwrapped input's. The app states this invariant itself — `backend/sequence_text.py` exists precisely because "every endpoint and GUI call site that analyses the same template box has to agree on which characters are the molecule and which are layout".*

## Root cause

`backend/routers/analysis.py:501`

```python
seq = sequence.strip().upper().replace(" ", "").replace("\n", "")
```

`\r` survives. So does `\t`, and so do the ORIGIN line numbers.

This is the exact line `backend/sequence_text.py` was written to replace. Its module docstring is the app's own statement of the invariant:

> One definition of what a pasted sequence *is* (#86).
>
> Every endpoint and GUI call site that analyses the same template box has to agree on which characters are the molecule and which are layout, or the same paste gets two different sets of coordinates…

and its comment names this precise expression as the thing that was wrong:

> Stripping anything less (the old `.replace(" ", "").replace("\n", "")` left `\r`, `\t` and the ORIGIN line numbers behind) means slicing a string Biopython never saw.

`normalize_template` (`backend/sequence_text.py:26`) strips `string.whitespace + string.digits` and upper-cases. The restriction endpoints were migrated to it when #86 was closed. **`find_orfs` was not.** Nor were the three sibling analysis endpoints that repeat the same expression at `backend/routers/analysis.py:581`, `:626` and `:765`.

This is the same defect class as #86 in a different endpoint — a different router, a different function, and a distinct observable consequence — not a duplicate of it. #86 is closed and its fix is correct; it simply did not reach here.

## Structural note

`backend/sequence_text.py` deliberately normalises **layout only** — its docstring says a leftover FASTA header or an `X` is left in place for `validate_template` to refuse (#87). Migrating `find_orfs` to `normalize_template` fixes this issue and nothing else; in particular it does **not** fix RNA input, which is filed separately, because `U` is a base and not layout. Whether `find_orfs` should also gain `validate_template`'s refusal (#87's shape) is a judgement for the fix — but with `normalize_template` alone, a codon can no longer contain a carriage return.
