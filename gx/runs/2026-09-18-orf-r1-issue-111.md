**Severity: high — an edit anywhere in a mitochondrial record silently rewrites a stored protein's first residue, and the record then round-trips out of the app disagreeing with NCBI's at the one position every downstream tool checks first.** The other 12 CDS features of the rCRS match NCBI byte for byte, which is what isolates this to the initiator rule rather than to the table or the coordinates.

Found by the Rockin-Robin `oligolia-gx-tests` contract, ORF/translation round 1, against commit `8424c4d`.

## Requirement

**OR-14** — *`restated_translation` reproduces NCBI's own protein for every CDS of NC_012920.1: all 13 `/translation` qualifiers, byte for byte, under the `/transl_table=2` each feature declares. This covers the minus strand (MT-ND6, `[14148:14673)`), six spans that are not a multiple of three because the stop codon is completed post-transcriptionally (MT-ND1, ND2, COX3, ND3, ND4, CYTB), and the initiator-methionine convention (MT-ND2 starts ATT, which gc.prt marks a table-2 start and which NCBI therefore writes M).*

## Root cause

`backend/services/annotations.py:92`

```python
return str(Seq(coding).translate(table=table, to_stop=True))
```

No `cds=True`, and no rewrite of the first residue. So the initiator codon is rendered as the amino acid it codes for *mid-chain*, not as the methionine the GenBank `/translation` convention requires.

MT-ND2 opens on **ATT**. gc.prt's `sncbieaa` for table 2 marks ATT as a START codon:

```
name "Vertebrate Mitochondrial" ,
ncbieaa  "FFLLSSSSYY**CCWWLLLLPPPPHHQQRRRRIIMMTTTTNNKKSS**VVVVAAAADDEEGGGG"
sncbieaa "----------**--------------------MMMM----------**---M------------"
```

Biopython's second rendering agrees: table 2's `start_codons=["ATT", "ATC", "ATA", "ATG", "GTG"]`. NCBI therefore writes `M` at residue 1 even though ATT is isoleucine everywhere else in the chain. `Bio.Seq.translate(cds=True)` implements exactly this rule; `translate(table=2, to_stop=True)` does not.

## Why this is not cosmetic — the interaction with #95

`restated_translation` exists to **restate a `/translation` qualifier after an edit** (#95: *"editing inside a CDS keeps the old `/translation`"*). Its own docstring says a feature whose claim cannot be restated should be dropped *"rather than carry a protein that no longer follows from the bases under it"*.

So the failure mode is not "a tool prints the wrong letter". It is:

> A user loads NC_012920.1, edits the record **somewhere that does not touch MT-ND2 at all**, and MT-ND2's stored `/translation` is silently rewritten from `MNPLAQ…` to `INPLAQ…`.

The edit is unrelated. The rewrite is silent. The exported GenBank then disagrees with NCBI's record at residue 1 of a CDS the user never touched, and nothing in the app says so. Whatever fix #95 lands for "re-derive the protein after an edit" will propagate this defect to every CDS with a non-ATG initiator — and under table 2 four of the five start codons are non-ATG (`ATT`, `ATC`, `ATA`, `GTG`), under table 11 six of seven.

## Traced to

`backend/services/annotations.py:92` — `Seq(coding).translate(table=table, to_stop=True)`, called from `restated_translation` (`backend/services/annotations.py:66`).

A naive `cds=True` will not drop in unchanged: six of the thirteen rCRS spans are not a multiple of three and have no terminal stop codon (`/transl_except=(…,aa:TERM)`), and `cds=True` requires a whole number of codons ending in a stop. Those six currently pass. The initiator rule has to be applied without losing the ragged-end handling at `backend/services/annotations.py:89` that makes them pass.

## Structural note

This function is the *good* translation path in the app — it reads `/transl_table` off the feature and trims a ragged trailing codon before translating. `find_orfs` (`backend/routers/analysis.py:499`) does neither; see the sibling issues on the missing genetic-code parameter and the run-off intervals. If those are fixed by converging the two paths onto one translator, this initiator rule must be part of the converged one, not left behind in the caller.
