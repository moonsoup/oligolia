**Severity: medium — the user-facing message states an arithmetic impossibility (5 residues are 15 bases, not 17) and the only signal that 2 bases were discarded is a Python warning written to a stream a desktop user never reads.** The app already knows the right shape of this: one of its two translate paths trims explicitly and documents why; the user-facing one does not.

## Requirement

**OR-15** — *The translate edit operation handles a trailing partial codon explicitly. `POST /sequences/{id}/edit` with `operation='translate'` on a 17-base sequence must either refuse the input or say in its result that a partial trailing codon was dropped. Reporting "Translated 17 nt → 5 aa" — which is arithmetically impossible, 5 residues being 15 bases — while emitting Biopython's "Partial codon" warning to a stream a desktop user never reads, is neither.*

## Root cause

`backend/routers/sequences.py:119`

```python
new_seq = str(bio_seq.translate(to_stop=True))
```

No trim, so Biopython raises its warning; and `backend/routers/sequences.py:122`

```python
message=f"Translated {len(seq_str)} nt → {len(new_seq)} aa",
```

reports the *input* length against the *output* length with nothing reconciling them. The warning goes to `warnings`; the message goes to the user. They disagree, and only one of them is visible.

The GUI duplicates the same call rather than going through the router — `gui/panels/sequence_panel.py:1077-1079`:

```python
elif op == "translate":
    result = str(bio.translate(to_stop=True))
    msg = f"Translation ({len(seq_str)} nt → {len(result)} aa)"
```

so fixing the router alone leaves the desktop path unfixed. Both have to change, or the GUI has to stop duplicating the router.
