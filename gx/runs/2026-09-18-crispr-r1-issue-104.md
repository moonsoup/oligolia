Found by the `oligolia-gx-tests` differential round on CRISPR (round 1). Not fixed here — this is a report, with a sealed failing test attached.

## Symptom

`on_target_score` is a single field of a single `GuideRNA` model. It is coloured by
one set of GUI thresholds (≥0.6 green, ≥0.4 amber, else red) and exported under one
TSV column. Three different functions write it.

Take any guide `/crispr/design` returns and paste it into `/crispr/score_guide`.
For AsCas12a, **9 of 10** come back with a different number; for LwaCas13a, **10 of
10** do. The app disagrees with itself about the same 23-mer.

A green Cas12a row means "GC is between 40 and 70 per cent". A green Cas13 row means
"GC is between 40 and 60 per cent". A green Cas9 row means something else entirely.
They are painted the same green.

## Requirement

**CR-9** (`gx/crispr/register.json`):

> One field, one scale. `on_target_score` is a single field of a single GuideRNA model, coloured by one set of thresholds in the GUI (>=0.6 green, >=0.4 amber, else red) and exported under one TSV column. For any guide the app returns from /crispr/design, the number in that field must equal what the app's own /crispr/score_guide returns for the same sequence. A design call that scores AsCas12a and LwaCas13a guides with a different function from the one /crispr/score_guide uses puts two incomparable scales in one column.

## Differential evidence

Input: `gx/corpus/inputs/puc19_L09137.2.txt` (2,686 bp, digest below), `max_guides=10`,
canonical guide lengths (Cas12a 23, Cas13 22). Both endpoints called in-process.

| cas type | guides disagreeing | example guide | `/crispr/design` | `/crispr/score_guide` |
|---|---|---|---|---|
| AsCas12a | **9 of 10** | `GGTGATGACGGTGAAAACCTCTG` | **0.6** | **0.68** |
| LwaCas13a | **10 of 10** | `CGTTTCGGTGATGACGGTGAAA` | **0.6** | **0.7** |
| SpCas9 | 0 of 10 | — | — | — |
| SpCas9-HF1 | 0 of 10 | — | — | — |

And the design-side numbers are not merely different, they are **two-valued**. Over
all 75 AsCas12a candidates in pUC19 the design endpoint emits only `{0.4, 0.6}`
(56 sites at 0.6, 19 at 0.4); over all 2,665 LwaCas13a candidates only `{0.5, 0.6}`.
Sorted by `max_guides`, that is a flag, not a score — which is the mechanism behind
the separate "ten shifted copies" issue.

## Where it is

Three scales behind one field, in `backend/routers/crispr.py`:

| scale | written at | formula |
|---|---|---|
| Cas9 / Cas9-HF | `:112`, `:128` | `_doench_rule_set1_score(guide_seq)` (`:16-47`) |
| **AsCas12a** | `:154`, `:168` | `round(0.5 + (0.1 if 40 <= gc <= 70 else -0.1), 3)` — **inline**, two-valued |
| **LwaCas13a** | `:185` | `round(0.5 + (0.1 if 40 <= gc <= 60 else 0.0), 3)` — **inline**, two-valued, different window |

…and one more on the other endpoint:

- `backend/routers/crispr.py:222` — `/crispr/score_guide` runs
  `_doench_rule_set1_score` on whatever it is handed, regardless of nuclease. It has
  no `cas_type` parameter at all (`:218`, signature is `score_guide(guide_sequence: str)`).

Consumers that assume one scale:

- `gui/panels/crispr_panel.py:192` — one threshold set for all four nucleases:
  `QColor("#1e3a2e") if score >= 0.6 else QColor("#3d2a00") if score >= 0.4 else …`
- `gui/panels/crispr_panel.py:112-114` — one column header, "On-target".
- `gui/panels/crispr_panel.py:233` — one TSV column, `on_target_score`.

The sharper illustration is the Cas13 case: `/crispr/score_guide` will happily apply
a Doench SpCas9 model to a 22 nt Cas13 crRNA, which is not a thing Rule Set 1 is
defined for either — see the separate CR-8 issue on what that function actually is.

## Relationship to the other on-target issues

Three distinct root causes, filed separately because each survives the others being
fixed:

- **This issue (CR-9):** two endpoints, one field, different functions. Fixed by
  routing every branch through one scorer that takes the nuclease into account, or
  by giving `/crispr/score_guide` a `cas_type` so it can answer the same way
  `design` does.
- **CR-8:** the function the Cas9 branch *does* share is named after Doench Rule Set 1
  and is not it. Unifying the scales does not make the shared function correct.
- **CR-10:** `max_guides` returns ten shifted copies of one locus. A degenerate score
  is the proximate cause on the Cas13 path, but the selection has no spacing
  constraint regardless of what the score becomes.
