**Severity: high — a default-reachable checkbox that gives wrong biology in both directions at once.** `include_all_starts=True` is offered to the user as "every start codon", and the set it actually uses is not any NCBI translation table: it misses a start codon table 1 declares and invents one it does not.

Found by the Rockin-Robin `oligolia-gx-tests` contract, ORF/translation round 1, against commit `8424c4d`.

## Requirement

**OR-6** — *`include_all_starts=True` draws its start codons from the genetic code in force, not from a free-floating list. gc.prt's `sncbieaa` for table 1 marks exactly three codons M: ATG, CTG and TTG. So with `include_all_starts=True` and table 1, a CTG-initiated ORF must be found and a GTG-initiated one must not (GTG is a start in tables 2 and 11, not in table 1).*

## Root cause

`backend/routers/analysis.py:507`

```python
start_codons = {"ATG", "GTG", "TTG"} if include_all_starts else {"ATG"}
```

That set is not a table. NCBI's own `sncbieaa` string for table 1 marks M at exactly ATG, CTG and TTG:

```
name "Standard" ,
sncbieaa "---M------**--*----M---------------M----------------------------"
-- Base1  TTTTTTTTTTTTTTTTCCCCCCCCCCCCCCCCAAAAAAAAAAAAAAAAGGGGGGGGGGGGGGGG
```

Biopython's second rendering of the same table agrees: `start_codons=["TTG", "CTG", "ATG"]`.

`{ATG, GTG, TTG}` is a strict subset of table 2's `{ATT, ATC, ATA, ATG, GTG}` ∪ table 11's `{TTG, CTG, ATT, ATC, ATA, ATG, GTG}` and is equal to neither, and `find_orfs` cannot be asked for either table (see the sibling issue on the missing genetic-code parameter). So under the only code this function implements, the flag's answer is wrong two ways simultaneously — **CTG is dropped, GTG is added**.

The 64 amino-acid assignments in `GENETIC_CODE` (`backend/routers/analysis.py:382`) are themselves correct — OR-1 checks all 64 against gc.prt and passes. It is only the start set that was written from memory rather than read off the table.

## Structural note

The fix is not just "swap GTG for CTG". `GENETIC_CODE` is a bare codon→amino-acid dict with no start set, so there is nowhere for a start codon to be *derived from*; any literal written next to it will drift the same way. Biopython already ships the machine-readable form — `Bio.Data.CodonTable.unambiguous_dna_by_id[table].start_codons` — and Biopython is already a dependency. This issue and the missing genetic-code parameter are the same table-handling gap seen from two sides and will likely be fixed by the same change.
