**Severity: medium-high — a reported interval whose bases are not the reported protein, and no way to tell a partial CDS from a complete one.** Any consumer that slices a reported ORF back out of the sequence gets a ragged string that Biopython refuses to translate cleanly, and "this reading frame runs off the end of what you gave me" is reported under exactly the same shape as "this is a whole protein".

Found by the Rockin-Robin `oligolia-gx-tests` contract, ORF/translation round 1, against commit `8424c4d`.

## Requirement

**OR-9** — *Partial trailing codons are handled explicitly, not silently. Re-extracting any reported ORF's bases by index and translating them with `Bio.Seq.translate` must not raise `BiopythonWarning('Partial codon')`, and an ORF that reaches the end of the molecule without a stop codon must be distinguishable as partial from the result alone — a consumer must not have to re-derive the bases to learn that the reported protein is unterminated.*

## Root cause

One branch, two consequences. `backend/routers/analysis.py:549-566`:

```python
# Report open ORF that reaches end of sequence (no stop codon — partial CDS)
if orf_start is not None and len(orf_codons) >= min_length_aa:
    protein = "".join(orf_codons)
    if strand_sign == 1:
        abs_start = orf_start
        abs_end = len(strand_seq)
    else:
        abs_end = len(seq) - orf_start
        abs_start = 0
```

`abs_end = len(strand_seq)` on the plus strand and `abs_start = 0` on the minus strand are **the end of the molecule, not the end of the last translated codon**. The 1–2 bases past the final whole codon are inside the reported interval and outside the reported protein.

For a complete ORF the app's convention — established by OR-5, which passes — is that the span includes the terminating stop codon, so `length_nt == 3 * (length_aa + 1)`. For a run-off ORF there is no stop codon, so `length_nt` should be `3 * length_aa`. It is neither: it is `3 * length_aa + (1 or 2)`.

And the ORF model, `backend/routers/analysis.py:110-117`:

```python
class ORF(BaseModel):
    frame: int
    start: int
    end: int
    length_nt: int
    length_aa: int
    protein: str
    start_codon: str
```

No `partial` / `truncated` / `complete` / `has_stop` field. The comment on line 549 says *"no stop codon — partial CDS"*, so the distinction was understood at the point of writing and then not put in the model. The only way to recover it from the response is arithmetic on `length_nt` against a stop-inclusive convention that is documented nowhere — and per the paragraph above, the bases in the reported interval do not even satisfy that arithmetic.

These are one root cause: the run-off branch reports an unterminated ORF as if it were a terminated one, in the interval it emits and in the shape it emits it under. A fix that trims the interval without adding the flag leaves the two indistinguishable; a fix that adds the flag without trimming leaves the interval ragged.

## Structural note

`backend/services/annotations.py:66-92` (`restated_translation`) already does the right thing with a ragged end — `coding = coding[: len(coding) // 3 * 3]` before it translates, documented at `backend/services/annotations.py:74-76` as *"A trailing partial codon is dropped before translating, which is what `Bio.Seq.translate` does with it anyway, minus the warning."* `find_orfs` does not, and also does not read `/transl_table` the way that function does. **The app has two translation paths and only one of them handles this**; the fix may be to converge them rather than to patch the arithmetic in place.
