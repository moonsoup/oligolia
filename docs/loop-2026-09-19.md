## Drivers built (rockin-robin), all test-first

- `rr_fix_dispatch` — composes the fixer's task; a send-back round quotes the verifier
  verbatim and refuses to compose without a reason.
- `rr_fix_verify` — runs Codex under least privilege: exec and its own `out/` + tmp, **no
  network**, the issue handed over as a sha256-pinned snapshot, venv built before it starts.
  Capabilities are measured from the runtime's own event log and intersected with the
  claim; evidence that does not resolve is dropped; a touched tree, a verdict about another
  commit, or a sandbox looser than declared escalates. The harness can only lower a verdict.
- `rr_fix_close` — closes only on a `fixed` resolution, with the run record's evidence.
- `rr_gx` — trace, seal, check-seal, run. The seal pins the tests, their conftest files and
  every corpus source; a later round may append sources without breaking an older seal.
- `capabilityFloorWithPinnedIssue` / `resolveVerifiedFixPinned` beside the originals: a
  pinned, cited issue snapshot stands in for network access and nothing else.
- `remote_instance_bootstrap.py transfer-auth` — moves this machine's login into the
  container over stdin; `remote_start.sh` (Friday_tools) starts a stopped session.

## What it cost, and what bit

- **Account quota.** The remote runs on the transferred login, so it draws on the same
  session limit as the interactive session. The loop stopped at 21:46 UTC on 2026-09-19
  with "You've hit your session limit · resets 5am (UTC)", taking #89 and the ORF round
  with it.
- **Disk.** Each verification kept a ~0.6 GB clone + venv; fifteen of them filled the disk
  and one run failed with ENOSPC. The harness now drops the tree once the record is written.
- **Two orchestrator faults worth remembering:** dispatching the next fix on seeing the
  commit rather than the dispatch task finishing put two fixer sessions in one working
  tree; and an early verify left a stub run directory that blocked the real one.

## What this run taught the loop

- A party is busy until its dispatch task ends, not when its commit appears (#95/#96 overlap).
- Each sealed round needs its own pytest process; a bare `pytest gx/` collides on conftest names.
- Push the moment the gate is green: two 45-minute runs finished the work and died before
  pushing, stranding the commit in the container (#89, #96). The dispatcher now says so and
  allows 55 minutes.
- A cheaper fixer (`--model sonnet --effort low`) wrote a correct fix but did not carry the
  protocol: it deferred the gate once and ran out the clock once. Quality is held by the
  verification, but *completion* is not — keep fixers at the default model.
- Verification measured from the runtime's own event log, not the model's account of itself;
  and the harness may only ever lower a verdict.
